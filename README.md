# De9De9 Academy

A mobile app of short lessons and tips on what De9De9 sells: unblock a sink,
read an electrical panel, look after an air conditioner, perform a first card
trick. Each lesson lists the tools it needs with a link to the right shelf of
the store, says when to stop and call a professional, and ends with a quiz.

French and Arabic (right to left), with the store's brand and design tokens
(`laarrbbi/de9de9`, `docs/design/DESIGN-SYSTEM.md`) and the look of
de9de9.dz, the client's services site, as the store took it: a white
header over the teal band of 3D emoji discs, the display title with the
logo's roof and the tilted coral pill, each track opening on a teal arch with
its 3D scene, « Pourquoi ? », the « Besoin d'un pro ? » band with the pros,
the coral ribbon, the ant mascot and the teal wave footer. Every picture is
de9de9.dz's own, copied from the store (`apps/storefront/src/assets/`). Built like De9De9 Play:
one web codebase (`www/`), wrapped for iOS and Android with Capacitor. All
lessons ship inside the app, so it works offline.

## Run it

```bash
npm install
npm start          # builds the lessons, serves the app at http://localhost:5174
npm test           # lesson rules, French/Arabic parity, routes, storage, links (fast)
npm run test:e2e   # the screens in a phone-sized Chromium (Playwright)
```

`npm run test:e2e` needs Playwright's Chromium once: `npx playwright install chromium`
(or `CHROMIUM_PATH=/path/to/chromium npm run test:e2e` to use one already installed).
It is the WebView's engine, not a phone: Android's back button, the status bar
and the notch still need a check on a real device.

Open it in a phone-sized browser window, or on your phone over Wi-Fi at
`http://<your computer's IP>:5174`.

Native builds (after changing anything in `www/` or `content/`):

```bash
npm run android    # syncs and opens Android Studio
npm run ios        # same, opens Xcode
python3 scripts/app-icons.py   # only when the logo changes (needs Pillow)
```

Every `cap sync` and `cap copy`, including a plain `npx cap sync`, builds the
lessons first (the `capacitor:copy:before` script), so the app never ships
without them.

## Write a lesson

1. Create `content/lessons/fr/<track>/<lesson>.md` and the same path under `ar/`.
2. Copy the frontmatter of an existing lesson and fill it in:
   - `risk`: `low`, `medium` or `high`. Anything above `low` must have a
     `safety` rule and a `callAPro` list; the build refuses it otherwise.
   - `tools`: add `shelf:` to link a tool to the store (keys in `www/js/shelves.js`),
     only when that shelf really sells the tool. Check the store's catalogue
     first; a link to a shelf without the item is worse than no link.
   - `quiz`: 1 to 5 questions; `answer` is the index of the right option, from 0.
3. Write the body in Markdown: `##` sections, numbered steps, and a
   `> **Astuce** :` blockquote for a tip.
4. `npm run build` (or `npm run watch` while writing) checks the rules, and
   that both languages have the same lessons, quiz answers, tool links,
   sections, tips and tables.

Never rename or move a published lesson file: progress is saved under
`<track>/<file name>`, so readers would lose that lesson's progress.

`npm run watch` only watches `content/lessons/`. After editing
`www/js/tracks.js` or `www/js/shelves.js`, restart it.

To add a track: add it to `www/js/tracks.js` with its pictures (the
sub-category emoji of the same trade from the store's
`apps/storefront/src/assets/subcategory-emoji/`, or its group's from
`category-emoji/` when de9de9.dz has none, never a picture of something
else; the group's scene from `category-scene/`), copy them into
`www/assets/`, then write its lessons. A track's `shelf` can be `null` when no store shelf
sells its tools; the track screen then shows no shop button.

## How the app behaves

- **Back:** every screen is a history entry. The on-screen arrow and Android's
  back button (handled by `@capacitor/app`) go back one screen; on the home
  screen, Android's back button leaves the app. A link to a screen that is
  already behind the current one ("Retour au parcours") goes back to it
  instead of stacking it again, and taps in the 300 ms after a screen change
  are ignored, so a double tap only moves one screen.
- **Links out:** store and "find a professional" links open in the phone's browser.
- **Store links are off until the shop is online.** de9de9.dz is the
  client's services site; the shop has no public address yet. While
  `STORE_LIVE` is `false` in `www/js/config.js`, the app shows no store link:
  tools keep their names, the track's shelf button and the store card go.
  "Find a professional" still opens de9de9.dz. The lessons keep their
  `shelf:`, so turning the switch on brings every link back.
- **Status bar:** dark icons on every screen, over the white header, set
  once in `capacitor.config.json` (`SystemBars.style: LIGHT`, i.e. for a
  light background), so the phone's dark mode does not change them. The app loads no `@capacitor/core`
  JavaScript, so plugins can't be called from `www/js/` without vendoring it.
- **Language:** the first launch follows the phone's language (Arabic phones
  get Arabic). On iOS this needs `CFBundleLocalizations` in `Info.plist`,
  which lists `fr` and `ar`.
- **If it can't start:** after 4 seconds without a screen, `js/boot.js` shows
  a short message in both languages instead of a blank page.
- **Safe areas:** screens pad themselves away from the notch and the gesture
  bar (`--safe-area-inset-*` from Capacitor on Android, `env()` on iOS).

## Not done yet

- **Never built on a phone.** The app was tested in a phone-sized browser
  (Chromium, touch, 390×844), not in the Android emulator, Xcode or on a real
  device. Build it once on each and check the back button, the status bar,
  the notch and the links out.
- **Content review.** Have the lessons reread by the team in both languages,
  and the electricity and AC safety content by a qualified electrician and AC
  technician, before publishing.
- **Missing products.** The store's catalogue has no playing cards, no
  two-pole voltage tester (VAT, only a non-contact one), no head torch, leak
  detector, wire strippers or mixer cartridges. Those tools have no store
  link until the store stocks them; the magic track has no shelf at all.
  When they arrive, add the `shelf:` back in both languages.
- **Addresses.** The day the shop is online, set `STORE_URL` to its address
  and `STORE_LIVE` to `true` in `www/js/config.js`, then run `npm run test:e2e`
  (it checks every store link with the switch on, whatever its value), or
  point them at the De9De9 app's deep links once they exist. "Find a
  professional" opens the services site's home page.
- **App icon.** It is the plain De9De9 logo, so on a home screen only the name
  tells it apart from the store app. An Academy variant is a design decision.
  `resources/logo.png` is still the Figma rendition of the logo; inside the
  app it is the client's artwork (the store's `docs/design/brand/logo-master.png`),
  which the icons should use when they are made again.
- **Progress is per phone.** It is not tied to De9De9 accounts.
- **Store listing.** App ID `com.avalonlbs.de9academy` (same owner as De9De9
  Play); no signing, store listing or screenshots yet.

## The parked website

`web/` holds the first version, an Astro website reading the same
`content/lessons/`. It is not maintained while the Academy is an app; delete
the folder if the website is not coming back.
`cd web && npm install && npm run build` still builds it.
